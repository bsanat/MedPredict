# API MedPredict — предварительный контракт

В исходном репозитории сервера и документации не было. POST ниже взят из задания/отчёта. GET — **предложение фронтенда, не утверждённый контракт Оралхана**. Реальная интеграция будет завершена после согласования и проверки на Spring Boot.

## POST /api/v1/predictions

Content-Type: application/json. Поля запроса соответствуют `key` из GET; числовой ввод преобразуется в JSON number, select передаётся строкой, пустые необязательные поля не передаются. Для предварительного варианта:

```json
{
  "age": 52,
  "sex": "male",
  "bmi": 27.4,
  "totalCholesterol": 5.6,
  "glucose": 5.9
}
```

Успешный ответ (200):

```json
{
  "predictedValue": 134.2,
  "unit": "мм рт. ст.",
  "modelVersion": "1.0.0",
  "disclaimer": "Учебный прогноз. Не является диагнозом."
}
```

`predictedValue` — конечное число, `unit` — непустая строка, совпадающая с единицей GET. `modelVersion` и `disclaimer` необязательны; если присутствуют, должны быть непустыми строками. Ответы с неправильными типами или единицами не показываются как прогноз. Версия из GET не подставляется за отсутствующую версию ответа: результат должен относиться к фактически использованной модели. Постоянное предупреждение интерфейса не заменяется серверным.

Ошибка валидации (400):

```json
{
  "error": "VALIDATION_ERROR",
  "fields": [
    { "field": "age", "message": "Возраст должен быть от 18 до 90 лет" }
  ]
}
```

Диапазон 18–90 в этом сообщении — пример из задания, **не согласованное ограничение текущей демоформы**. Текст валидного ответа связывается с известным полем; неизвестное имя вызывает общую ошибку контракта. Текст выводится через React без HTML-интерпретации. Некорректная структура 400, не-JSON или неожиданное 2xx — общая ошибка ответа. 5xx — временная недоступность; другие неуспешные JSON-ответы — отклонённый запрос. Сетевой сбой, таймаут и пользовательская отмена различаются.

## GET /api/v1/model/info — предложение

```json
{
  "indicatorName": "Систолическое давление",
  "unit": "мм рт. ст.",
  "decimalPlaces": 1,
  "modelVersion": "1.0.0",
  "fields": [
    { "key": "age", "label": "Возраст", "type": "number", "unit": "лет", "required": true },
    {
      "key": "sex", "label": "Пол", "type": "select", "required": true,
      "options": [
        { "value": "male", "label": "Мужской" },
        { "value": "female", "label": "Женский" }
      ]
    },
    { "key": "bmi", "label": "Индекс массы тела", "type": "number", "unit": "кг/м²", "required": true },
    { "key": "totalCholesterol", "label": "Общий холестерин", "type": "number", "unit": "ммоль/л", "required": true },
    { "key": "glucose", "label": "Глюкоза", "type": "number", "unit": "ммоль/л", "required": true }
  ]
}
```

Все поля верхнего уровня обязательны, кроме `modelVersion`. `decimalPlaces` — целое от 0 до 20 (технический предел отображения) или явно `null` для сохранения исходной точности. Значение 1 в примере — только демонстрационная настройка, не утверждённая точность модели.

`fields` — непустой массив с уникальными `key`. Разрешённые имена: латинская буква, затем латинские буквы, цифры или `_`; `constructor`, `prototype`, `__proto__` запрещены. Порядок массива определяет порядок формы. У каждого поля обязательны `key`, `label`, `type`, `required`; необязательна непустая строка `hint`.

- `number`: обязательна `unit`; необязательны конечные `min`, `max`, булево `integer`. min не больше max. Без этих параметров нет медицинских ограничений.
- `select`: обязательны непустые `options` с уникальными непустыми `value` и непустыми `label`.

Новые числовые/списковые показатели не требуют менять компоненты: форма и payload строятся по GET. Другие типы полей потребуют согласованного расширения. Если описание отсутствует/невалидно, ввод и POST недоступны: интерфейс предлагает повторить GET.

## Поведение и приватность

Базовый origin берётся из `VITE_API_BASE_URL`; путь `/api/v1` уже входит в endpoints. Пустой origin использует origin сайта. Таймаут действует на запрос и чтение тела ответа. `AbortController` обеспечивает отмену, изменение ввода, размонтирование; идентичность запроса дополнительно блокирует запоздалые результаты. Одновременно выполняется максимум один POST. Автоматических повторов и переключения в демо нет.

Реальный режим передаёт только показатели на настроенный сервер. Нет localStorage/sessionStorage, аналитики, логирования формы, URL-параметров с показателями. Заголовки и сообщения не содержат ключей или медицинских значений. Настройка окружения публична, секреты в ней недопустимы.

## Что согласовать с командой

| Вопрос | Ответственный |
|---|---|
| Окончательный показатель, набор признаков и единицы | Али + Оралхан + команда |
| min/max, целочисленность, обязательность, варианты пола из датасета | Али, затем серверная валидация Оралхана |
| Методология и точность отображения | Али |
| Формат GET, POST и 400, согласованность единиц, версии | Оралхан + Санат |
| CORS, URL окружений, HTTPS, таймауты и эксплуатация | Оралхан |
| Хранение и логи сервера, обработка медицинских данных | Оралхан + команда |
| Локализация названий полей на казахский | Санат + команда |

Нельзя выводить из этого примера клиническую точность, категорию здоровья, вероятность болезни или доверительные интервалы. Сервер остаётся источником окончательной валидации.
