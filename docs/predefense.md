# Вклад Бөгенбаева Саната — предзащита 24 октября 2026

Общий комплект анализа и планирования: [оглавление предзащиты](README.md). Этот файл описывает frontend-вклад Саната; он не подтверждает готовность backend/модели, интервью или отзыв руководителя. Проект задач: [YouTrack MED](https://medpredict.youtrack.cloud/issues/MED).

## Завершённая фронтенд-часть

Спроектирован и реализован пользовательский путь: знакомство → форма → исправление ошибок → отправка → ожидание → результат/ошибка → изменение и повторный запрос. Подготовлен визуальный макет (`design/concept.png`) и адаптивный интерактивный прототип React + TypeScript + Vite на русском, казахском и английском языках.

Реализованы конфигурируемые поля, единицы измерения, обязательность, числовой ввод с десятичной запятой, доступные сообщения об ошибках, обработка серверной валидации, отдельный API-слой с проверкой ответов, таймаут, отмена и защита от повторных и устаревших запросов. Интерфейс не хранит медицинские значения между сессиями и не отправляет их в аналитику.

Подготовлены инструкция запуска, предварительный контракт с сервером, описание пути пользователя и автоматические проверки. Макет и прототип показывают вклад в UX и фронтенд; они не являются экспериментальными результатами нейросети.

## Демонстрация на предзащите

1. Запустить `npm ci` и `npm run dev`, открыть http://127.0.0.1:5173.
2. Показать заметную отметку «Демонстрационный режим» и ограничения.
3. Отправить пустую форму: показать ошибки и фокус первого поля.
4. Заполнить синтетический пример 52 / Мужской / 27,4 / 5,6 / 5,9.
5. Отправить: показать обработку, фиксированное значение 134,2 и предупреждение.
6. Изменить показатель: результат исчезнет; сделать повторный запрос.
7. Отменить запрос во время обработки; показать сохранённую форму.
8. Для серверной ошибки сменить `.env.local` на `VITE_DEMO_SCENARIO=validation` или `unavailable`, перезапустить Vite.
9. Показать мобильную компоновку и документацию API.

Фиксированный пример 134,2 одинаков для любого технически валидного ввода. Не представлять его как персональную оценку или результат обученной нейросети.

## Совместная интеграция — следующий этап

- Баймен Али: утверждение целевого показателя, данных и признаков, обучение/оценка модели, обоснование точности отображения и ограничений.
- Сеилхан Оралхан: Java/Spring Boot endpoints, окончательная серверная валидация, подключение модели, CORS и окружения, политика обработки данных.
- Санат: согласование предложенного GET, проверка фронтенд-адаптера на работающем сервере, обновление конфигурации и сквозная проверка после подключения модели.

На этом этапе подтверждены взаимодействия интерфейса и его обработка тестовых ответов. Работающая модель, точность прогнозирования и успешная интеграция с настоящим сервером не заявляются.
