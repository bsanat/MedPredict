# Начальная спецификация требований MedPredict

Версия 0.1 от 16 октября 2026. Основание: существующий frontend и требования к предзащите из предоставленного документа. Это проект требований команды; пользовательские интервью и утверждение руководителя ещё ожидаются.

Приоритеты: Must — без этого минимальный сценарий не принимается; Should — нужно для текущего прототипа, но не доказывает качество модели; Later — отдельный этап. «Реализовано» ниже означает наличие в frontend, а не сквозную работоспособность с настоящей моделью.

## Функциональные требования

| ID | Требование | Приоритет | Проверяемый критерий приёмки | Состояние и свидетельство |
|---|---|---|---|---|
| FR-01 | Показывать назначение, режим и ограничения до ввода | Must | На главной и форме виден режим; demo прямо назван фиксированным примером; предупреждение сохраняется у результата | Реализовано; `tests/demo.spec.ts` |
| FR-02 | Строить real-форму по валидному описанию модели | Must | Без успешного GET ввод/POST недоступны; поля, порядок и единицы совпадают с GET; ошибку GET можно повторить | Адаптер реализован; `tests/api.spec.ts`; контракт GET предложен, не согласован |
| FR-03 | Проверять ввод до отправки | Must | Обязательные поля не пусты; точка/запятая преобразуются в число; некорректные/бесконечные значения отклоняются; min/max/integer применяются только из конфигурации | Реализовано; `src/validation.test.ts` |
| FR-04 | Отправлять один явный запрос и проверять ответ | Must | Валидная отправка создаёт один POST с JSON number/string; повторные нажатия во время обработки не создают POST; неверные типы/единицы ответа не показываются как результат | Реализовано на подменённых ответах; `src/api/api.test.ts`, `tests/api.spec.ts` |
| FR-05 | Разрешать отмену и редактирование без устаревшего результата | Must | Отмена, изменение ввода или уход со страницы исключают показ позднего ответа; ввод сохраняется в памяти; новый POST требует отправки | Реализовано; `tests/demo.spec.ts` |
| FR-06 | Давать исправить ошибки без повторного ввода всей формы | Must | Ошибка известного поля связана с ним; фокус на первом проблемном поле; сеть/timeout/5xx дают общую ошибку; real не переходит в demo | Реализовано на подменённых ответах; `tests/api.spec.ts` |
| FR-07 | Показывать проверенный результат и его контекст | Must | Видны число, согласованная единица, отправленные значения и предупреждение; версия ответа показывается только при её наличии; изменение данных скрывает результат | Реализовано; `tests/api.spec.ts`, `tests/demo.spec.ts` |
| FR-08 | Экспортировать существующий результат в PDF | Should | PDF содержит язык интерфейса, снимок ввода, единицы, результат и предупреждение; повторный POST не создаётся; ошибка экспорта позволяет повторить | Реализовано; `src/pdf/report.test.ts`, E2E |
| FR-09 | Поддерживать три языка и навигацию | Should | RU/KK/EN переводят клиентский интерфейс и demo; переходы сохраняют ввод/язык в памяти; перезагрузка очищает значения | Реализовано; `src/i18n/i18n.test.ts`, E2E; серверные тексты требуют соглашения |
| FR-10 | Подключить настоящий backend и утверждённую модель | Must для интегрированного проекта | Настоящие GET/POST проходят согласованный контракт, ошибки и отмену; результат совпадает с прямым вызовом той же версии модели на контрольных данных | Ожидается backend/модель; PLAN-05, PLAN-11 |
| FR-11 | Ввести аккаунты, историю и удаление после согласования | Later | До отдельного API действия отключены и не имитируют успех; после согласования нужны отдельные требования к доступу и хранению | Интерфейсы отключены; вне текущего минимального сценария |

## Нефункциональные требования

| ID | Требование | Приоритет | Критерий приёмки и способ проверки |
|---|---|---|---|
| NFR-01 | Ограничить распространение введённых показателей | Must | В frontend нет localStorage/sessionStorage, аналитики, логов и URL с показателями; demo не отправляет их по сети; real отправляет только настроенному API; проверить код и сеть на синтетике |
| NFR-02 | Проверять данные на границах компонентов | Must | Неизвестные/некорректные метаданные, дубли ключей, неверные единицы и неконечные ответы отклоняются; сервер независимо валидирует запрос; unit + будущие backend-тесты |
| NFR-03 | Обеспечить доступность основного сценария | Must | Сценарий проходится клавиатурой; виден фокус, ошибки связаны с полями, смена состояния объявляется; ручной скринридер ещё требуется. Полное соответствие WCAG не заявлено |
| NFR-04 | Поддерживать узкие экраны | Should | На ширинах 320 и 390 px нет горизонтального переполнения основного интерфейса; 1440 px сохраняет читабельную компоновку; синтетический E2E |
| NFR-05 | Ограничить ожидание и исключить скрытые повторы | Must | При превышении настроенного timeout запрос завершается сообщением; по умолчанию 15000 мс; отмена отличима от timeout; нет автоматического повтора POST или fallback в demo |
| NFR-06 | Сделать проверку воспроизводимой | Must | На записанной версии запускаются typecheck, lint, unit, build; E2E фиксируют браузер и размеры; эксперимент модели фиксирует данные, split, seed, код и baseline |
| NFR-07 | Не выдавать прототип за клиническое средство | Must | Нет диагноза/лечения/обещания точности; demo помечен; опубликованные метрики относятся к указанной выборке/модели и сопровождаются ограничениями |
| NFR-08 | Согласовать эксплуатационные ограничения до real-публикации | Must до публикации | Backend-команда документирует TLS, CORS, доступ, логирование, хранение/удаление и окружения; реальные данные не используются до согласования. В этом репозитории ещё не подтверждено |
