## 4 Подготовка тега без его создания

Порядок для команды после отдельного разрешения: проверить `git status`, выбрать согласованную базу, рассмотреть новые и ранее незакоммиченные файлы, выполнить только необходимые проверки, разрешённо зафиксировать принятый комплект и получить peer review. Затем записать SHA сдаваемого commit, ограничения и нерешённые задачи. Тег не может обозначать незакоммиченные Word/Markdown.

Только после выполнения этих условий и прямого разрешения на создание тега допустима ручная команда `git tag -a pre-defense-1 <утверждённый-SHA> -m "MedPredict first pre-defense 2026-10-24"`. Значение в угловых скобках — заполнитель, команду нельзя копировать без замены на проверенный SHA. Push требует отдельной авторизации; здесь не выполнялся. Перед созданием убедиться, что тег отсутствует; существующий сдаваемый тег не перемещать и не перезаписывать.
