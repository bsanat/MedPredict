# Управление проектом и риски MedPredict

План первой предварительной защиты 24.10.2026. Срез состояния 16.10.2026, часовой пояс Asia/Almaty. Даты последующих этапов — предложение команды, не утверждённый календарь AITU.

## 1 База планирования и состояние

Официальная тема: «Разработка интеллектуальной системы прогнозирования медицинских показателей на основе нейронных сетей». AITU требует к 24 октября анализ, проектирование, планирование, свидетельства вклада и научного контроля; готовое приложение на этом этапе не требуется. Источник — [предоставленные требования](../pre-defense/evidence/university-requirements-extract.md).

Подтверждены локальная React/TypeScript/Vite-реализация, макет Figma и demo с фиксированным 134,2. В checkout нет исходников Java backend, весов моделей, данных обучения или экспериментальных результатов. Сообщение команды о разработке backend/ML записывается отдельно от проверенных локальных артефактов. Указанные проценты готовности не назначаются без принятой базы оценки.

Документационный комплект подготовлен к рассмотрению. ФИО руководителя Турарова Маржан Кабдыкалиевна подтверждено командой 16.10.2026. Реальные обсуждения, документ назначения/отзыв руководителя, согласование API/данных и фактическое назначение YouTrack-задач остаются открытыми. Существовавшие незакоммиченные изменения сохранены; новые файлы не означают публикацию в GitHub.

## 8 GitHub и выпуск версии

Подтверждённая ссылка пользователя — [bsanat/MedPredict](https://github.com/bsanat/MedPredict), основная ветка по GitHub metadata — main. Локальная работа на figma-design; origin пока содержит прежнее имя владельца. Переименовывать remote, переносить репозиторий или публиковать изменения автоматически нельзя. Для единого проекта backend и модель следует согласованно включить в тот же репозиторий с сохранением авторства, если это соответствует организации команды и требованиям AITU; их отсутствие здесь нужно объяснить на защите.

После получения разрешения работать от согласованной базы main в ветках вида `codex/MED-<реальный-ID>-описание`. Коммит или PR содержит действительный ID задачи, цель изменения, способ проверки и ограничения; задача ссылается обратно на PR/commit. Другой участник проверяет существенные командные изменения до merge. Каждый использует собственный аккаунт; оценка вклада не подменяется числом коммитов.

Локальная история на момент осмотра показывает автора juniorqazaq; это свидетельство доступной истории, не доказательство отсутствия работы Али/Оралхана вне checkout. Их индивидуальный вклад пока требуется подтвердить соответствующими артефактами, авторством и review. Недопустимы задние даты, фиктивные PR или переписывание истории для имитации постепенной работы.

Тег `pre-defense-1` сейчас не создаётся. Перед его разрешённым созданием: согласовать содержимое, зафиксировать все сдаваемые материалы в commit, выполнить нужные проверки, сохранить ограничения/открытые задачи и проверить доступ. Аннотированный тег должен указывать точный принятый commit; после сдачи его не перемещать. Команды для ручного выполнения и условия приведены в checklist; commit/push/tag/merge/branch в этой работе не выполнялись.

## 9 Определение завершённости

Документационный результат завершён, когда все 11 материалов имеют читаемые исходники и Word-версии, источники проверяемы, требования связаны с архитектурой/планом оценки, диаграммы редактируемы, а пробелы явно указаны. Это не равнозначно готовности университета принять работу.

Для первой защиты дополнительно нужны реальные обсуждения и научный отзыв, актуальный README, назначенные задачи, индивидуальный вклад, доступ и точная сдаваемая версия. Модельный инкремент отдельно принимается по воспроизводимым метрикам и проверенной интеграции.
