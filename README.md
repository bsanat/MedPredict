## О проекте

MedPredict — дипломный проект студентов **Astana IT University**. Этот репозиторий содержит frontend-часть Бөгенбаева Саната. Сервер Java / Spring Boot и модель разрабатываются другими участниками команды.

Знакомство → ввод → проверка → отправка → результат. Данные остаются в памяти текущей вкладки.

**Текущий статус — учебный прототип.** В demo значение **134,2 мм рт. ст.** является фиксированным примером для проверки интерфейса. Оно не рассчитывается по введённым данным. Окончательный показатель, модель и медицинские диапазоны ещё согласуются; прогноз не является диагнозом и не заменяет консультацию врача.

## Быстрый запуск

Нужны **Node.js 22.12+** и **npm**.

```sh
git clone https://github.com/juniorqazaq/MedPredict.git
cd MedPredict
git switch Sanat
npm ci
npm run dev
```

Откройте **[127.0.0.1:5173](http://127.0.0.1:5173)**. Локальный demo явно включён в `.env.development`. Нажмите **«Перейти к форме»**. Форма изначально пустая; для проверки используйте пример ниже.

Синтетические данные для демонстрации:

| Возраст | Пол | ИМТ | Общий холестерин | Глюкоза |
|---|---|---|---|---|
| 52 | Мужской | 27,4 | 5,6 | 5,9 |

В demo нет согласованных медицинских диапазонов: технически допустимый ввод не означает медицинскую корректность.

## Работа с API

Для собственной конфигурации скопируйте шаблон:

```sh
cp .env.example .env.local
```

| Переменная | Назначение |
|---|---|
| `VITE_API_MODE` | `demo` или `real`; обязательна |
| `VITE_DEMO_SCENARIO` | `success`, `validation` или `unavailable`; обязательна в demo |
| `VITE_API_BASE_URL` | Origin сервера; пустое значение использует origin сайта |
| `VITE_API_TIMEOUT_MS` | Таймаут API; по умолчанию `15000` мс |

После изменения `.env.local` перезапустите Vite. `VITE_*` попадает в браузерный код — не используйте эти переменные для секретов.

<details>
<summary><strong>Демонстрационные сценарии</strong></summary>

```dotenv
VITE_API_MODE=demo
VITE_DEMO_SCENARIO=success
```

- `success` — фиксированный пример результата.
- `validation` — фиксированная ошибка возраста независимо от ввода; это тест интерфейса, а не медицинская проверка.
- `unavailable` — сценарий недоступного сервиса.

Demo не отправляет показатели сетевыми запросами и не обращается к модели.

</details>

<details>
<summary><strong>Подключение Java / Spring Boot</strong></summary>

```dotenv
VITE_API_MODE=real
VITE_API_BASE_URL=http://localhost:8080
VITE_API_TIMEOUT_MS=15000
```

| Запрос | Назначение |
|---|---|
| `GET /api/v1/model/info` | Описание показателя, полей, единиц, точности и ограничений |
| `POST /api/v1/predictions` | Отправка проверенных значений и получение результата |

GET пока предложен frontend и требует согласования с Оралханом. Полный формат запросов, ответов и ошибок — в [контракте API](docs/api-contract.md).

Без валидного описания модели форма и POST недоступны. Ошибка real не переключает приложение в demo; автоматических повторов POST нет. Междоменное подключение требует CORS на сервере. Auth и история пока не входят в согласуемый контракт прогноза.

Поля и медицинские диапазоны определяет сервер. `decimalPlaces: null` сохраняет точность полученного числа; min/max/integer применяются только при наличии в конфигурации. В real названия полей, единицы и произвольные сообщения API показываются как получены — их перевод требует серверного соглашения.

</details>

## PDF и приватность

После успешного ответа кнопка **«Скачать PDF»** формирует текстовый A4 с логотипами, датой документа, показателем, отправленными значениями и единицами, результатом, версией ответа при наличии и учебным предупреждением. Demo явно помечен как фиксированный пример. Дата документа не подменяет время прогноза.

Экспорт использует снимок проверенного запроса и существующий ответ, без повторного POST и диалога печати. Подготовка блокирует повторный экспорт; ошибка позволяет попробовать снова. Изменение данных, уход с результата и смена языка отменяют незавершённый экспорт. Папку сохранения определяет браузер.

- Показатели и язык хранятся только в памяти React. Перезагрузка или закрытие вкладки очищает ввод.
- Нет хранения показателей в `localStorage`, `sessionStorage`, аналитике или frontend-логах; данные не помещаются в URL.
- Real отправляет значения только настроенному серверу. Политику хранения и логирования на сервере определяет backend-команда.
- PDF содержит экспортированные пользователем показатели. Шрифт Noto Sans и логотипы загружаются локально; кириллица и казахские буквы поддерживаются.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run build
npx playwright install chromium  # один раз, если браузер ещё не установлен
npm run test:e2e
```

E2E используют два временных Vite-сервера на `4173` и `4174`, desktop `1440×1200` и mobile `390×844`; проверки узких экранов включают `320 px`. В real-сценариях ответы API подменяются, поэтому Spring Boot для этих тестов не нужен. Все примеры синтетические.

Фактические результаты и ограничения проверок: **[docs/verification.md](docs/verification.md)**. Работающий сервер, обученная модель и их сквозная интеграция пока не проверены в этом репозитории.

<details>
<summary><strong>Сборка и локальный preview</strong></summary>

Для demo-сборки сохраните `.env.local` с `VITE_API_MODE=demo` и `VITE_DEMO_SCENARIO=success`:

```sh
npm run build
npm run preview
```

Переменные должны быть заданы до сборки: Vite встраивает их в браузерный код. В production нет режима по умолчанию; отсутствие конфигурации показывается явно.

</details>

## Структура

```text
src/
  pages/        главный экран
  components/   поля, результат, SVG-иконки и общие элементы интерфейса
  hooks/        состояние запросов и отмена
  api/          HTTP/demo-адаптеры и проверка ответов
  config/       конфигурация окружения и предварительный показатель
  i18n/         переводы kk / ru / en
  pdf/          текстовый отчёт A4
  validation.ts преобразование и проверка ввода
public/         логотипы, флаги и локальные шрифты
tests/          браузерные пользовательские сценарии
docs/           API, UX, дизайн и отчёты о проверках
```
